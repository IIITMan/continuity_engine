# ENGINE_CONTRACTS.md

版本：0.2.0  
状态：架构基线；高优先级决策已冻结

## 1. 系统边界

Continuity Engine 是持续状态与自主行为编排层。它负责把经过处理的观测转化为状态更新、候选意图和受约束的行动请求，并根据动作回执更新后续决策。

它不直接承担：

- 原始音频/视频的完整感知模型推理（由感知服务负责）。
- 实时电机控制、硬实时避障或安全急停（由独立控制/安全系统负责）。
- 无约束的 LLM 输出执行。
- 未经验证的事实写入长期记忆。

## 2. 核心不变量（MUST）

1. 每个持久状态字段有唯一权威写入者。
2. 每次状态提交必须通过类型、范围、时间与跨字段校验。
3. `NaN`、正负无穷、非法范围和未知枚举值不得进入已提交状态。
4. 事件具有稳定 ID，并有重复处理策略。
5. 动作命令与动作结果是两件事；必须由有 ID 的回执确认状态。
6. 当前意图不能因一次普通驱力波动而无条件改变。
7. 用户取消会使对应请求/结果版本失效，并触发执行器取消流程。
8. 安全监督器可以否决动作，普通驱力、情感与 LLM 输出不能覆盖否决结果。
9. LLM、网络或非关键传感器不可用，不应导致核心状态循环永久阻塞。
10. 需要跨重启保留的用户偏好和记忆必须持久化并有删除路径。

## 3. 建议模块与状态所有权

| 模块 | 权威状态/职责 | 不可直接做的事 |
|---|---|---|
| Event Router | 事件入队、去重、顺序和处理状态 | 修改驱力或意图 |
| World Model | 事实候选、来源、置信度、有效期、不确定状态 | 把无来源推断升级为已确认事实 |
| Drives | 驱力值、目标、紧迫度和更新时间 | 直接发起硬件动作 |
| Prediction | 预测记录、模型版本和学习统计 | 直接改写用户事实或强制切换意图 |
| Policy/Will | 当前意图、候选决策、状态转移 | 绕过安全检查直接执行动作 |
| Action Executor | 动作生命周期与执行回执 | 将命令已发送当作动作已成功 |
| Memory | 事件记忆、长期事实、摘要及来源链接 | 未经策略检查保存全部 LLM 推断 |
| Personality | 慢变量个体参数及更新审计 | 被单次短期情绪直接大幅修改 |
| Affect | 情感状态与表达调节信号 | 覆盖安全或用户控制约束 |
| LLM Gateway | LLM 请求状态、输出校验与关联 ID | 直接提交内部状态或绕过 Policy |
| Safety Supervisor | 动作许可/拒绝与拒绝原因 | 由普通业务模块覆盖 |
| Persistence | 状态快照、事务、版本与恢复记录 | 未校验即恢复旧状态 |

## 4. 事件契约

每个事件至少需要：

- `event_id`：全局唯一 ID。
- `kind`：版本化的事件类型。
- `source`：传感器、用户、执行器、内部调度器等来源。
- `timestamp_mono`：适用于同一开机周期内的持续时间计算。
- `timestamp_wall`：日历时间记录。
- `payload`：符合事件类型 schema 的结构数据。
- `confidence` 或明确的确定性/不确定性语义。
- `correlation_id`：关联对话、意图或动作（如适用）。
- 处理去重键、有效期和优先级策略。

事件类型 MUST 区分瞬时事件与持续状态。例如，`person_detected` 不等于 `person_entered`；`speech_started` 不等于完整的用户指令；`action_requested` 不等于 `action_completed`。

### 4.1 冲突与陈旧数据

世界模型至少应表示：`CONFIRMED`、`PROBABLE`、`UNKNOWN`、`STALE`、`CONFLICT`。数值置信度与业务状态分开管理。

不同来源的数值不能直接平均，除非已定义可解释且校准过的融合模型。来自同一模型或同一原始帧的重复输出不应被当作独立证据。

事件过期应按语义类型配置。过期的“当前有人”观测通常降为未知/陈旧状态，而不是自动转换成“无人”。

## 5. 时钟与调度

- 单调时钟用于 `dt`、deadline、冷却期和超时。
- 墙上时钟用于日期、昼夜和事件展示。
- `dt < 0` MUST 拒绝；非有限 `dt` MUST 拒绝。
- 过大的 `dt` 按状态类别单独处理，禁止使用一个全局截断值处理所有状态。
- 可解析更新的变量采用解析更新；需要积分的变量可进行受限子步；依赖观测的状态在停机期间不虚构更新。
- 后台任务可延迟/取消，不得阻塞用户取消、核心状态和安全路径。

## 6. 驱力契约

驱力字段至少包括：`value`、`target`、`urgency`、`updated_at`。字段取值范围由 schema 固定，第一版可统一归一化到 `[0, 1]`。

驱力更新必须区分：

1. 时间自然变化。
2. 事件引发的变化。
3. 行动结果导致的需求满足或未满足。

同一事件不可经过多个模块重复累加。驱力可以影响候选意图分数，但不得绕过可行性、安全和用户控制检查。

## 7. 意图状态机

建议状态：`PROPOSED`、`RUNNING`、`WAITING`、`INTERRUPTED`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`EXPIRED`。

- `NO_ACTION` 是合法的无当前前台意图状态。
- 每个意图必须有目标、唯一 ID、创建时间、状态、取消/超时策略及恢复策略。
- 新意图需通过候选生成、可行性检查和切换策略。
- 普通切换可使用 `switch_margin`、`min_dwell_time` 和连续确认机制。
- 当前任务完成、失效、用户取消或高优先级事件发生时，可进入不同的中断/重新评估路径。
- 被中断意图必须声明恢复策略：`RESUME_IF_VALID`、`REPLAN`、`DROP` 或其他明确定义的策略。
- 意图状态转移必须可审计，并记录原因与相关事件 ID。

## 8. 动作执行契约

每个动作至少包括：`action_id`、`intent_id`、类型、参数 schema、创建时间、deadline、取消 token 和幂等键（如适用）。

动作结果至少区分：`SUCCEEDED`、`FAILED`、`CANCELLED`、`TIMED_OUT`、`UNKNOWN`。

`UNKNOWN` 表示系统没有足够证据确认成功或失败。不得把它默认为成功。

取消请求与确认停止是不同状态。对于有实体风险的动作，执行器应返回停止确认或故障结果。

## 9. 安全监督器契约

安全监督器返回结构化结果：

- `ALLOW`
- `DENY_HARD`
- `DENY_NEED_INFO`
- `DENY_TEMPORARY`

必须附带稳定的拒绝代码和可审计原因。`DENY_HARD` 不允许原样重试；信息不足时可以补齐信息；临时条件不满足时可等待或选择安全替代动作。

## 10. 故障处理

- 单次非法输入：拒绝输入，状态不提交。
- 更新结果出现 `NaN`/无穷/越界：拒绝候选状态。
- 非关键模块短窗口重复产生非法结果：隔离该模块，输出降级状态，进入健康检查。
- 关键状态不可恢复或安全路径异常：停止依赖该状态的非必要动作，并进入受控降级。
- 不允许仅因经过固定时间而自动恢复模块；必须通过健康检查。
- 日志应包含错误类别、模块、关联 ID、状态版本和恢复动作；敏感原始内容应按隐私策略过滤。

## 11. 持久化与恢复

持久化数据须带 schema 版本、引擎版本和写入时间。恢复流程必须：

1. 加载快照与待恢复任务。
2. 校验 schema 和字段合法性。
3. 重新评估观测有效期。
4. 将不可恢复的短期动作标记为过期/未知。
5. 对长期偏好和记忆执行完整性检查。
6. 通过状态验证后才恢复主动行为。

恢复失败时优先进入安全的基础模式，不应通过默认值伪造旧事实。


## 12. 其他第一版强制决策（详见 ARCH_DECISIONS.md）

- LLM 只能读取由 `StateViewBuilder` 生成的、按 purpose 过滤的不可变状态投影；禁止原始完整快照序列化。
- 事件必须携带 `event_schema_version`；第一版基线为 `1.0`，采用显式顺序迁移和原子提交。未知未来 major 版本拒绝恢复并保留原始数据。
- 回放模式禁止真实 LLM、外部网络与真实硬件执行器；允许 loopback/Unix-domain 本地 IPC，以兼容运行时事件循环；不支持混合回放。
- 配置只允许白名单非安全参数热重载；安全、隐私、权限、schema、队列容量和存储 backend 需重启并审查。
- 记忆删除必须重算可追溯派生状态；无法重算的受影响预测分区重置为冷启动。
- 安全、停止、取消、静音以及动作终态回执不得进入可任意丢弃的普通队列；安全/停止还需独立 latch/控制路径。
- 每个意图最多两轮澄清；超限后使用安全默认或停止，不允许无限追问。
