# Continuity Engine 工程基线文件（v0.2）

本目录将 Continuity Engine 的讨论整理成可进入工程评审的初始文件集。

## 文件清单

- `PRODUCT_CONSTRAINTS.md`：产品边界、交互约束、隐私与用户控制要求。
- `ARCH_DECISIONS.md`：7 项高优先级架构决策的冻结答案与验收标准。
- `ENGINE_CONTRACTS.md`：模块职责、状态所有权、事件、意图、动作和故障处理契约。
- `config/default.yaml`：第一版可配置参数基线。
- `LLM_INTEGRATION.md`：LLM 网关、请求生命周期、上下文、工具权限与降级策略。
- `ACCEPTANCE_TESTS.md`：测试矩阵、起始验收阈值、测试方法和通过条件。

## 重要说明

1. 这是 **v0.2 工程基线提案**，不是已经验证过的产品规格，也不是完整的生产级安全认证文件。
2. 默认产品假设：桌面陪伴机器人；第一版不自主移动；具有麦克风、扬声器、物理控制入口；摄像头按需启用；基础状态管理本地运行；LLM 可以使用云端服务但不是基本控制的运行前提。
3. 配置中的时间常数、阈值、延迟、频率、资源预算等均属于初始假设，需要经过目标硬件测量、场景测试和用户体验测试后再冻结。
4. 物理安全、隐私和当地法规要求需根据最终产品形态、部署国家/地区、传感器与实际执行器另行审查。
5. 本基线有意把“硬约束”和“效用评分”分开：禁止动作不能因为效用分数高而被执行。

## 建议使用方式

1. 产品负责人先审阅并确认 `PRODUCT_CONSTRAINTS.md` 中标为 `TBD` 的项目。
2. 工程负责人对 `ENGINE_CONTRACTS.md` 做接口评审，并将其转化为类型定义、状态机与代码审查规则。
3. 开发环境统一读取 `config/default.yaml`，避免在各模块散落硬编码。
4. LLM 接口实现必须遵守 `LLM_INTEGRATION.md`，执行器与安全模块不接受未经验证的自由文本命令。
5. CI 先实现 `ACCEPTANCE_TESTS.md` 中的确定性单元和集成测试，再启用自主主动互动功能。
6. `ARCH_DECISIONS.md` 中的 AD-001 至 AD-007 属于第一版契约；如需更改，必须更新配置、实现与对应测试。

## 状态标记约定

- **MUST**：必须满足的架构或安全约束。
- **SHOULD**：强烈建议；如不遵守，必须记录原因。
- **BASELINE**：建议起点，需要实测调整。
- **TBD**：当前信息不足，必须由产品/工程负责人确认。


## v0.2 已冻结的 7 项高优先级决策

1. LLM 仅读取按 purpose 过滤的不可变状态视图。
2. 事件 schema 版本化，按显式迁移函数原子升级。
3. 回放模式禁止真实网络、LLM 与硬件副作用。
4. 只允许白名单非安全参数热重载。
5. 记忆删除必须重建派生状态或重置受影响模型分区。
6. 安全/停止/取消/静音/动作终态事件走保留通道与必要的独立 latch。
7. 每个意图最多两轮澄清，超限后安全降级。
