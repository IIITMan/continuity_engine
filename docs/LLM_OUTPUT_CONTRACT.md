# LLM 输出契约与重试策略

版本：0.11.1-dev

## 原则

- 每个请求目的有独立、固定的 JSON 输出结构。
- JSON 必须可解析，顶层必须是对象，字段必须与该目的的契约完全匹配。
- 生命引擎按字段、类型、长度、枚举及上下文 allowlist 校验结果。
- 不合格结果直接丢弃，不会交给动作执行层。
- 普通 LLM 请求最多重试 2 次（总计最多 3 次尝试），并把不含原始输出的校验错误代码提供给下一次请求。
- `task_plan` 使用任务规划器已有的有界修复流程，避免重复叠加重试。
- 网络、认证和服务端错误不作为格式错误无限重试；重试次数受限。达到上限后返回失败/拒绝状态，不使用无效结果。

## 输出结构

- `simple_response` / `complex_dialogue`：`{ "response_text": "..." }`，仅允许一个非空字符串字段。
- `multi_step_plan`：`{ "steps": [...] }`，仅允许一个顶层字段；每个步骤按既定步骤契约校验，工具必须来自 allowlist。
- `task_plan`：`{ "steps": [...] }`，由任务规划器进一步校验动作类型、参数字段、枚举、范围和 allowlist。
- `memory_consolidation`：`{ "candidate_memories": [...] }`，仅允许一个顶层字段；每条候选记忆必须满足来源引用及字段约束。

## 提示词修复规则

当上一次输出不合格时，系统提示词会追加一条严格修复指令；上下文只包含简短校验错误，不会把被拒绝的原始输出当作有效数据继续使用。

## 当前策略状态

交互状态仅驻留内存。程序重启后不自动恢复，不新增磁盘持久化或恢复逻辑。
