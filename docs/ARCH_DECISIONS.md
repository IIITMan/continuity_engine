# ARCH_DECISIONS.md

版本：0.2.0
状态：第一版工程决策（适用于桌面静态机器人 MVP）

本文件专门冻结第一行核心代码前必须确定的 7 项决策。除非版本升级并更新测试，不得由各模块自行采用不同解释。

## AD-001：LLM 只能读取按任务过滤的状态视图

**决定：第一版不允许 LLM 读取或序列化原始完整 `StateSnapshot`。** 所有 LLM 上下文必须由 `StateViewBuilder` 按 `purpose` 从显式字段白名单中生成投影视图。

- 常规对话只包含当前话语、必要的最近对话、相关用户偏好、当前任务摘要和相关记忆引用。
- 计划请求额外包含目标、已确认世界事实、相关约束、允许工具及必要的任务进度。
- 记忆整理只读取指定时间窗内、带来源 ID 的候选事件。
- 不传入完整驱力向量、完整内部状态、全量事件流、无关人物信息、原始音视频或秘密凭据。
- 不向 LLM 暴露可直接写入的可变对象；视图是不可变、版本化、按用途校验的数据传输对象。
- 任何新增字段必须在相应 purpose 的 allowlist、隐私审查和测试中显式注册。

验收：序列化器只能输出该 purpose 的 schema 字段；未知字段默认拒绝；日志可记录字段名而不记录敏感字段值。

## AD-002：事件 schema 版本与迁移

**决定：所有持久化事件都必须包含 `event_schema_version`，第一版基线为 `1.0`。** schema 使用显式向前迁移函数，不依赖读取时的隐式猜测。

- 兼容的可选字段增加可以升 minor 版本；字段语义变化、删除或类型改变必须升 major 版本。
- 持久化事件按顺序执行版本迁移：`vN -> vN+1`；每个迁移函数必须有单元测试、输入/输出校验和版本记录。
- 迁移在事务或新存储副本中执行；迁移成功并校验后才切换，不允许半迁移数据被主引擎读取。
- 未知的未来 major 版本：拒绝主动恢复该数据，保留原始文件/记录并进入受控降级；不得静默丢字段后继续。
- 不可迁移的旧事件进入隔离区并记录原因；不得把无法解析的事件伪造成默认事实。
- 第一版不支持在线跨进程、多版本 schema 协商；数据格式升级必须跟随应用版本发布与迁移脚本。

验收：旧版本 fixture 能正确迁移；未来版本数据会被拒绝而非被破坏；迁移中断可回滚或从未切换的旧副本恢复。

## AD-003：回放模式彻底禁止真实 LLM 与硬件副作用

**决定：第一版提供离线回放模式，且回放模式不允许真实网络调用、真实 LLM 请求或真实硬件动作。**

- 通过依赖注入选择 `ReplayLLMAdapter`、`SimulatedActionExecutor`、固定时钟和可控随机数生成器。
- 回放只允许读取本地 fixture 和写入独立的临时/回放数据库；不使用生产凭据，不连接生产外设，不访问外部网络。
- 运行时若检测到 replay mode 却注入了真实 LLM、真实动作适配器或非白名单网络客户端，启动必须失败。
- 回放输入应包含事件序列、配置版本、schema 版本、seed、录制的 LLM 返回（如有）和期望断言。
- 回放不再次调用真正的 LLM；LLM 结果只能来自 fixture 或确定性的 stub。
- 第一版不支持“半回放半真实执行”的混合模式。

验收：测试期间断言没有外部网络出站、真实 LLM provider 调用或硬件适配器调用；任何违反都会使测试失败。

## AD-004：热配置重载白名单

**决定：第一版允许有限热重载，但只允许非安全、非隐私、非结构性参数。** 重载采用整份配置校验后原子切换，禁止逐字段部分可见。

允许热重载（通过 schema 校验后，在下一决策边界生效）：
- 普通主动发言频率与冷却时间；
- 非安全类驱力时间常数、目标与普通候选门槛；
- 普通意图切换阈值、表达映射、Affect 滞回参数；
- 非安全类 LLM token 预算和普通请求超时（不得超出产品硬上限）。

第一版禁止运行时热重载（需要停机/重启，并经过相应审查）：
- Safety Supervisor 的规则、硬件安全限值和紧急路径；
- 工具 allowlist、权限、隐私上传白名单与数据保留/删除策略；
- event/state schema 版本、状态所有权规则、持久化 backend；
- 事件队列容量/保留通道配置、replay/live 模式；
- 认证凭据、网络信任设置和密钥。

重载行为：先对完整候选配置做 schema、范围、跨字段约束检查；分配新的 `config_version`；原子切换；记录变更者、字段名、旧/新配置版本和时间（不记录秘密值）。活动中的动作不被追溯改写；新参数从下一次决策边界生效。失败时整份拒绝，继续使用最后一个有效配置。

验收：无效配置不会部分生效；安全/隐私字段热重载请求被拒绝；活动任务只在定义好的边界采用新普通参数。

## AD-005：记忆删除必须处理派生状态

**决定：第一版支持有来源追踪的派生状态重建；对无法追溯或无法可靠重建的受影响聚合状态，采取重置到冷启动，而不是保留可能泄漏已删除记忆影响的旧统计。**

- 事件记忆、摘要、检索索引和派生记录都保存源 memory/event ID 或可追溯 lineage。
- 删除先生成 deletion job，锁定目标范围，标记为不可被新检索读取，再删除主记录与索引、缓存和可定位的摘要引用。
- 对预测统计模型：按剩余有效样本重建受影响 key/partition；若无逐条贡献日志或重建失败，则重置对应 key/partition 到冷启动参数。
- 对关系/个性派生状态：第一版默认不自动在线学习个性（`personality.update_enabled=false`）；若删除影响可追溯关系统计，则从剩余来源重算；无法可靠重算时，将相关字段重置为基线并写审计记录。
- 删除不得影响无关用户或其他主体的数据。
- 删除后不得声称已清除离线备份，除非备份也具备可定位删除或按政策到期清除；产品界面应准确显示完成范围。
- 任何删除流程失败时，目标记忆必须保持不可被普通检索使用，并报告部分失败/待完成，不得假报成功。

验收：删除后重新查询无目标记忆；摘要和索引无残留引用；预测模型要么由剩余来源重建，要么对应分区被重置；不保留无法解释的旧贡献。

## AD-006：事件过载与不可丢弃事件

**决定：安全、停止、取消、静音控制以及动作终态回执不进入可任意丢弃的普通事件队列。** 它们使用保留控制通道；安全/停止信号还必须有独立的 latch/控制路径。

事件处理顺序：
1. 过期且尚未处理的普通事件先丢弃。
2. 可替换的持续观测（如某目标最新位置）按 key 合并，只保留最新有效状态。
3. 重复的非副作用遥测与低价值周期样本合并或丢弃。
4. 普通低优先级环境观察按明确优先级丢弃，并记录计数。
5. 用户请求/动作结果等重要事件触发背压、保留通道或显式错误处理，不得静默丢弃。
6. 安全/停止/取消事件使用 reserved lane 和独立 latch；如果控制通道本身不可用，则触发安全降级，并依赖独立硬件/系统安全路径，不能继续假定事件已处理。

队列上限与保留容量是静态启动参数，第一版不支持热重载。不得承诺在进程崩溃、内存损坏或硬件失效时仍由应用队列保证事件；物理安全停止必须由独立控制路径提供。

验收：普通队列满时，STOP/CANCEL/MUTE 和安全 latch 仍然可设置并先于普通工作处理；低优先级丢弃有指标与日志；动作终态结果不会静默丢失。

## AD-007：澄清问题最大轮次

**决定：每个 `intent_id` 最多发起 2 轮澄清问题。** 同一意图中不得重复询问语义相同的问题；计数写入意图状态并跨重启保留。

- 澄清轮次按“机器人提出一个需要用户回答的澄清问题”计数；一条消息内的多个紧密相关子问题视为一轮，但应尽量只问最必要的内容。
- 达到上限后，低风险任务可采用预先定义的安全默认值，或说明仍缺少的信息并停止执行。
- 高风险、不可逆、对外有副作用或涉及隐私权限的操作，如果关键条件仍不明确，必须停止执行，不能通过猜测补全。
- 用户提供新信息并明确开始一个新意图时，才开启新的轮次计数；不能靠内部重建 intent ID 绕过上限。
- 第一版不支持无限澄清循环或让 LLM 自行决定无限追问。

验收：单个意图最多产生两轮澄清；第三轮候选问题被策略层拒绝，并转为安全默认、说明无法继续或等待用户发起新任务。

## 冻结与变更

这些决策是第一版默认契约。变更需要更新本文档版本、配置版本和对应验收用例，并在代码审查中记录变更原因。
