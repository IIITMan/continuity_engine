# LLM_INTEGRATION.md

版本：0.2.0  
目标：让 LLM 提供复杂认知与自然语言能力，但不成为生命引擎的唯一运行前提或无约束控制器。

## 1. 职责边界

LLM 可用于：

- 复杂语言理解、指代消解、用户意图解释和必要的澄清问题。
- 开放式计划生成与候选方案比较。
- 自然语言表达。
- 生成候选记忆摘要和经验假设。

LLM 不得直接：

- 修改权威内部状态、信任值或个性参数。
- 将自己的推断直接提交为已确认世界事实。
- 绕过用户取消/静音设置。
- 绕过安全监督器执行动作。
- 直接发出未经过 schema、权限、可行性与安全检查的硬件命令。
- 决定停止/急停的唯一触发路径。

## 2. 请求分类与上下文预算

初始 token 预算为 BASELINE，实际预算应按所用模型的分词方式、上下文窗口及输出预留调整。

| purpose | 必要上下文 | 初始预算 |
|---|---|---:|
| `simple_response` | 当前输入、互动设置、最少对话上下文 | 2,000 |
| `complex_dialogue` | 当前输入、相关对话、当前任务、相关记忆引用 | 4,000 |
| `multi_step_plan` | 目标、当前状态、依赖、允许工具、约束、必要历史 | 6,000 |
| `memory_consolidation` | 指定时间范围内、带来源的候选事件 | 4,000 |

上下文构建器必须按目的选择字段，不能直接序列化整个状态或全部记忆。需明确标出事实、推断、未知和过期信息。每条重要记忆应携带来源引用或 memory ID。

## 3. 请求生命周期

每个请求至少包含：

- `request_id`
- `interaction_id`
- `intent_id`（如适用）
- `generation` 或任务版本
- `purpose`
- `created_at_mono`
- `deadline_mono`
- `status`
- `cancel_token`

请求状态：

`CREATED -> RUNNING -> COMPLETED | FAILED | TIMED_OUT | CANCELLED | STALE`

规则：

1. 用户取消、任务过期或新 generation 取代旧请求后，旧结果必须标记为无效。
2. 收到返回结果时，必须再次校验 interaction/intent/generation 是否仍然匹配。
3. 请求取消不代表外部工具调用已取消；工具调用必须有独立 action ID 和回执。
4. 有副作用的工具调用需要幂等键，并区分“请求已提交”与“执行结果未知”。
5. 仅对可安全重试的请求进行有限重试。首版最多 1 次重试，不能无限重试。
6. 限制并发数量，避免新旧请求积压。

## 4. 输出结构与验证

按不同 purpose 使用不同 JSON Schema。不要使用一份巨大且可修改任意状态的通用 schema。

推荐输出类别：

- `InterpretationResult`：候选意图解释、歧义和需要澄清的问题。
- `PlanProposal`：候选步骤、前置条件、所需工具及预期结果。
- `ResponseProposal`：候选文本、风格标签、关联事实引用。
- `MemoryProposal`：候选摘要、来源 memory IDs、事实/推断分类。

验证顺序：

1. JSON/Schema 校验。
2. 关联 ID 和请求版本检查。
3. 来源和事实引用校验。
4. 用户偏好与隐私策略检查。
5. 工具权限白名单检查。
6. 可行性检查。
7. 安全监督器检查。
8. 批准后才提交对应动作或记忆写入请求。

LLM 返回的 `confidence` 只是模型自报字段，不能直接作为已校准概率使用。需要校准时，应通过独立评估验证。

## 5. 安全否决与重新规划

安全监督器返回结构化结果：

- `DENY_HARD`：硬性禁止，原动作不得原样重试。
- `DENY_NEED_INFO`：缺少必要信息，可以请求澄清或生成补充方案。
- `DENY_TEMPORARY`：当前条件不满足，可等待或选择安全替代动作。

首版最多允许 1 次针对结构化拒绝原因的重新规划。重新规划仍需经过完整校验与安全检查；不能让 LLM 自己判定被拒绝的动作现在就变得安全。

## 6. 超时与离线降级

建议首版请求超时 12 秒、最多 1 次有限重试；具体值需按目标模型与产品延迟目标实测。

LLM 不可用时：

- 停止、取消、静音和本地状态更新继续可用。
- 规则明确的简单回应可用本地模板。
- 开放式复杂计划暂停或明确告知暂时不可用。
- 记忆整理延后。
- 不应因 LLM 故障重复执行可能产生副作用的工具动作。
- 任何高风险硬件控制都不依赖 LLM 完成安全判断。

## 7. 上下文注入与提示注入风险

外部用户消息、检索记忆、网页摘要及工具返回都必须被视为数据，而不是系统策略。工具权限来自本地配置，不由 LLM 的文本声明决定。

不要把秘密、凭据、无关人物信息或全部原始传感器内容放进上下文。对检索结果中的指令类文本，不允许其改变工具白名单或安全规则。

## 8. 成本与可观测性

每个请求记录：模型/版本、purpose、输入输出 token（若提供）、耗时、重试次数、取消/过期状态、schema 结果、工具调用 ID 和错误类别。

默认不在普通日志中写入完整敏感 prompt、原始音视频或不必要的个人信息。成本统计应基于聚合数据及最小必要字段。

## 9. 必须实现的测试

- 旧请求在用户取消后返回，不产生动作。
- 同一意图新 generation 取代旧 generation，旧结果被标记 `STALE`。
- 无效 JSON/错误 schema 被拒绝。
- LLM 建议越权工具，被本地白名单拒绝。
- 安全监督器返回 `DENY_HARD`，不进行相同动作重试。
- 超时与重试不会重复触发有副作用的工具调用。
- 网络断开时本地停止、取消、状态更新仍然可用。
- 记忆摘要无法提供来源时，不自动写入长期事实。


## 10. 状态快照访问策略（强制）

LLM **只能读取按 purpose 生成的过滤摘要视图**，不得读取/序列化原始完整 `StateSnapshot`。所有请求必须经过 `StateViewBuilder`，视图使用不可变 DTO 和对应 JSON Schema。未在该 purpose 的 allowlist 中的字段默认拒绝。常规请求不得包含完整驱力向量、整库记忆、全量事件流、原始音视频、秘密凭据或无关人物信息。新增字段必须经过隐私审查、更新 allowlist 和测试。详细决策见 `ARCH_DECISIONS.md` 的 AD-001。

## 11. 澄清轮次上限（强制）

每个 `intent_id` 最多进行 2 轮澄清问题。计数在意图状态中持久化；同一意图不得重复提出语义相同的问题。达到上限后，低风险任务采用安全默认或明确说明缺少的信息并停止；高风险、不可逆、隐私敏感或具有外部副作用的任务在关键条件不明确时必须停止，不得猜测继续。不得通过重建意图 ID 绕过计数。详细决策见 `ARCH_DECISIONS.md` 的 AD-007。

## 12. 回放模式限制（强制）

回放模式使用 recorded fixture、确定性 stub、固定时钟和模拟执行器；禁止真实 LLM 请求、真实硬件调用和外部网络出站。不支持半回放半真实执行。启动时必须检查 adapter 与运行模式一致，否则失败退出。详细决策见 `ARCH_DECISIONS.md` 的 AD-003。
