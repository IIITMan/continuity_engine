# 技能开发规范（v0.12）

所有可插拔行为必须实现统一的异步技能接口，并由宿主引擎的 `SkillRegistry` 管理。技能不得自行决定路由、提升权限、绕过安全策略或直接修改引擎内部状态。

## 1. 接口约定

- `SkillSpec` 是技能声明：稳定的小写 `skill_id`、用途描述、所需权限、并发上限和可 JSON 序列化的元数据。
- 技能实现必须提供 `async execute(call: SkillCall)`。
- 推荐返回 `SkillResult`；宿主也接受 JSON 兼容的 mapping，并负责规范化为结果。
- 所有输入与输出必须是有界、可 JSON 序列化的数据，不得在结果中放入异常对象、文件句柄、设备对象、密钥或未经筛选的传感器数据。

## 2. 权限和安全

- 注册技能不代表授予权限。每次调度都由宿主比较 `required_permissions` 与本次调用获得的授权。
- 技能只能执行声明范围内的工作；不得自行请求或扩展权限。
- 设备控制、网络访问、文件访问、记忆写入等副作用必须在 `SkillSpec` 中声明所需权限，并接受引擎策略的授权与确认。
- 不可信参数必须在技能入口再次校验；不得把用户文本当作系统指令或可执行代码。
- 默认采用失败关闭：参数无效、权限缺失、依赖不可用或执行状态不确定时，不执行副作用，并返回明确错误码。

## 3. 生命周期与执行

- 技能必须支持异步调用；长耗时工作应尊重宿主超时和取消语义。
- 不要吞掉取消信号；不要在技能内部创建不受管理的后台任务。
- `SkillRegistry` 管理注册、启停、并发、超时、卸载和执行反馈。执行中的技能不可被卸载或替换。
- 技能不得直接把结果写入持续交互状态。执行结果先返回引擎，由引擎决定下一步行为。
- 不在模块导入时访问硬件、网络、文件系统或启动线程；依赖应在执行期显式注入。

## 4. 结果与错误

- 成功返回 `SkillStatus.OK` 和最小必要的结构化数据。
- 参数错误、依赖不可用、权限不足和执行失败使用稳定 `error_code`；消息可供诊断，但不得泄露秘密或原始异常。
- 结果应说明技能实际观察到/完成的事情，不得声称未验证的硬件动作已经成功。
- 幂等性和重试策略由技能文档明确说明；非幂等操作不能自行重试。

## 5. 测试最低要求

每个技能至少覆盖：有效输入、无效输入、权限拒绝、依赖失败、超时/取消（如适用）、输出 JSON 兼容性，以及无副作用或副作用边界。

## 6. 标准示例

参见 [`examples/skills/echo_skill.py`](../examples/skills/echo_skill.py)。该示例只回显文本，不访问设备或网络，用于演示技能接口、输入校验和结构化结果。真实设备技能必须额外提供硬件适配器与安全测试。
